# ShotServer web parity inventory

Phase 0 source audit for `replace-web-interface-with-wasm`. This is an inventory of behavior encoded in the current checkout, not a claim that every workflow has been exercised. **Source-audited** means the route dispatch, handler, and served page/API calls were inspected. **Runtime-unverified** applies to every row: no ShotServer instance, browser, device, or live account was operated for this inventory. Error cases below are source-visible branches; their wording and browser presentation have not been observed at runtime.

## Historical scope (2026-10-20)

Earlier `migrate`, `cutover`, or `fallback` wording in row dispositions describes the superseded replacement framing and is not authorized by the current change scope; interpret those rows only as workflow candidates and compatibility evidence.

## Coverage and unresolved Phase 0 items

- **Source-audited coverage:** all explicit top-level routes in ShotServer dispatch, the route families dispatched to handler files, the visible handler branches for bags, recipes, equipment, theme, layout/library/community and auth, and direct supporting API/file/event routes are represented above. Wildcard forms (`<id>`, `<key>`, `<filename>`, `<category>`) are parameterized route patterns, not omitted paths.
- **Runtime-unverified:** every user-visible field list above still needs inspection against the running legacy pages; status/error wording, browser navigation, mobile layout, uploads, downloaded bytes, SSE reconnection, auth expiry and actual native refresh behavior have not been tested. No device/browser versions or representative datasets have been recorded here.
- **Known parity risks from source:** theme and layout are richer on the web than their native settings counterparts; Bean Base search/find-page/AI extraction and image refresh are web-only workflows to account for; support pages expose downloadable logs, memory and conversation exports; browser file APIs and native picker/install flows differ. The native `SettingsPage.qml` is not assumed to cover the entire web `/settings` surface.
- **Additive route invariant:** `/wasm/` is the opt-in Wasm entry and route namespace. Existing application pages keep their current paths and HTML responses; there is no cutover, route remapping, default change, or HTML retirement in this change. APIs, MCP protocol/installers, event streams, icons/images, downloads, upload/restore handlers and other file routes remain real server endpoints. Unknown paths and API errors must not silently load the Wasm shell.
- **Gate 0 status:** this file provides a source-only inventory, not Gate 0 evidence. Hardware/browser inventory, exact field/action walkthrough, baseline measurements, dependency/toolchain audit, device checks and maintainer go/no-go remain unresolved. No task is marked complete by this document.
