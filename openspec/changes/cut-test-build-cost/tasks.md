- [x] 2.8 **ATTEMPTED AND REVERTED.** Stop `maincontroller.h` propagating the third-party `<MQTTAsync.h>` to its 16 includers. It uses `MqttClient` **only as a pointer** (`Q_PROPERTY` at :180, getter at :273, member at :714), so forward-declare it in the header and move `#include "../network/mqttclient.h"` into `maincontroller.cpp`. Do not pimpl `mqttclient.h` itself — it uses `MQTTAsync_successData*` and friends in real member declarations, so its own include is legitimate; the fix is to stop propagating it. Only 3 files use `MqttClient`'s API and 2 already include it directly. Found by hoisting `profilesavehelper.cpp` into `decenza_profilelib` (task 2.3), where the requirement stopped being invisible.
  - **Not viable. `Q_PROPERTY(MqttClient* mqttClient ...)` requires the complete type** — Qt's metatype system rejects an incomplete pointee ("Pointer Meta Types must either point to fully-defined types or be declared with `Q_DECLARE_OPAQUE_POINTER`"). The opaque-pointer escape hatch is worse than the include: `SettingsHomeAutomationTab.qml` reads through this property at 8 sites (`MainController.mqttClient.connected` / `.status` / `.connectToBroker()`), and an opaque pointer has no introspectable members, so all 8 would degrade at RUNTIME rather than fail to compile. The predicted `main.cpp` fallout (5 call sites) was real and trivial; the `Q_PROPERTY` is what kills it.
  - **Measured before reverting, as required: touching `mqttclient.h` rebuilds 65 edges / 26 compiles / 170 s cpu.** Real, bounded, and not worth a silent runtime regression. `maincontroller.h` now carries a comment recording all of this so the idea is not retried from scratch.
  - **Measure it, do not assume.** Touch `src/network/mqttclient.h`, rebuild, diff `.ninja_log` — before and after, same method as 1.2. "Fat header, obviously bad" is exactly the plausible-sounding claim this change refuses everywhere else. If the saving turns out trivial, **say so and keep the change anyway** on include-hygiene grounds, rather than reporting it as a build win it was not.
  - Watch for: callers relying on the transitive include (the compiler finds them; each needs its own `#include`), and that the QML registration path still resolves `MqttClient` as a type with only a forward declaration in `maincontroller.h`.

Fixed, and the parsed count is now cross-checked against a naive `grep -c '^add_decenza_test('` (106 = 106) with a hard refusal on mismatch. The guard was verified by making the parser drop a target and watching it refuse, not by watching it pass. Also confirm and that the failure message names the source and every target involved — a message naming only one target sends the reader to the wrong file.
