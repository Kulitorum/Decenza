## 5. User-profile encoding upgrade, on load

Sequenced last per design D6. This is the only work in the change that touches a user's disk.

> **Rescoped from a one-time startup pass to upgrade-on-load.** A one-time pass cannot be correct: a user drops profiles into the directory whenever they like — sideloaded, restored from a backup, synced from another device — so any pass that marks itself complete leaves every later arrival unconverted. Upgrading when a profile is actually loaded covers files that arrive at any time, needs no completion flag, and touches nothing the user never uses. **Task 5.3 (the completion flag) is deleted by this rescope, not deferred.**

- [x] 5.1 Make `Profile::saveToFile` atomic (`QSaveFile`: write to temp, `commit()` renames). It currently opens `WriteOnly`, truncating in place — tolerable for git-tracked built-ins, not for rewriting a user's file purely to reformat it, where a crash or full disk mid-write destroys a profile that was fine. Fixing it here rather than only at the call site protects every writer. Done — `QSaveFile` + `commit()`, with the failure path documented (a missing `commit()` is a silent no-op that reads as success).
- [x] 5.2 Add the upgrade to `ProfileManager::loadProfile`'s 4-tier resolve, scoped to the **writable** tiers: ProfileStorage (SAF), `userProfilesPath()`, `downloadedProfilesPath()`. Tier 4 (`:/profiles/`) is a read-only Qt resource and must be skipped. Deliberately **not** hooked in `Profile::loadFromFile` — 28 call sites outside `profile.cpp` read from resources, temp files and staging dirs, none of which should be rewritten. Done — `ProfileManager::upgradeStoredEncoding()`, called from `loadProfile` on the Storage/LocalFile tiers only, via an explicit `Origin` enum rather than inferring from the path.
- [x] 5.3 Write only when `Profile::jsonParityErrors(original, converted)` is empty. Audit before writing, never after — the `--rewrite-format` path documents why: an earlier revision wrote first and audited the file it had just clobbered, so by the time "DATA LOSS" appeared the original only existed in git. Done — parity checked against the bytes actually on disk, before any write.
- [x] 5.4 Skip silently when the stored object already equals the canonical one, so a loaded profile is not rewritten on every activation. Compare the parsed objects, not the bytes — formatting differences that survive a round trip would otherwise churn the file and its mtime forever. Done — compares parsed objects; verified by `loadDoesNotRewriteAnAlreadyCanonicalProfile`.
- [x] 5.5 Log a skip once per profile when parity fails, naming the profile and the keys at risk. A profile that cannot be converted losslessly is a signal about the serializer, not noise to swallow. Done — `qWarning` naming the profile and the drifting keys.
- [x] 5.6 Route the SAF tier through `ProfileStorage::writeProfile()`, not `QFile` — on Android the profile directory may be a SAF tree with no usable filesystem path. Done — `filePath.isEmpty()` selects the `ProfileStorage::writeProfile` path.
- [x] 5.7 Test: a legacy-encoded profile is upgraded on load; a deliberately lossy fixture is left untouched with a log line; an already-canonical profile is not rewritten; a built-in is never written. Done — 4 tests in `tst_profilemanager.cpp`: upgrade, no-rewrite-when-canonical, built-in untouched, lossy left byte-for-byte with an asserted warning.
- [x] 5.8 Verify a converted profile survives `DatabaseBackupManager`'s `copyDirectory()` into a backup and restores readable — the reason the conversion exists. Done — `upgradedProfileSurvivesABackupRoundTrip` copies the converted file and asserts `reaprimeReadabilityErrors` is empty on the far side.
